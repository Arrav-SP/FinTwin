# Phase 7 — Predicted-vs-Actual Validation

## Architecture

`validate_prediction.py` creates a reproducible `WorkloadConfig`, loads the measured Phase 4 model artifacts, stores the prediction, executes the same configuration with the Phase 2 `WorkloadRunner`, and attaches the Phase 3 `TelemetryCollector`. PostgreSQL is the source of truth for actual latency, throughput, CPU, and lock metrics. The persisted `validation_experiments` row links the prediction UUID to the actual `experiment_runs.experiment_id`.

## Integrity and lifecycle

Validation records move through `PENDING`, `RUNNING`, `COMPLETED`, or `FAILED`. A failed prediction or workload is not converted into an accuracy result. The configuration, model directory/warnings, timestamps, prediction, actual experiment, actual measurements, and errors are retained for reproducibility. No performance value is generated by perturbing a prediction.

## Error methodology

For each available target, absolute error is `abs(predicted - actual)`. Percentage error is absolute error divided by the absolute actual value, multiplied by 100. When actual is zero, percentage error is `null` while absolute error remains valid. Aggregate summaries include MAE, RMSE, R² when actual variance exists, and MAPE only for non-zero actual values. Results are grouped overall, by scenario, concurrency, and target TPS.

## Reproduction

```powershell
$env:PYTHONPATH = (Get-Location).Path
python scripts/initialize_database.py
python scripts/validate_prediction.py --scenario NORMAL_DAY --concurrency 10 --target-tps 10 --duration 10
python scripts/run_validation_suite.py --scenarios NORMAL_DAY SALARY_DAY --concurrency 10 --target-tps 10 --duration 10 --repetitions 1
python scripts/run_benchmark.py --scenarios NORMAL_DAY SALARY_DAY --concurrency 10 --target-tps 10 --duration 10 --format csv --output artifacts/benchmark.csv
```

The prediction CLI requires a complete measured model set under `artifacts/models`. If model artifacts are unavailable, the run is recorded as `FAILED`; this is intentional and prevents unsupported accuracy claims. A statistically meaningful validation report requires multiple real experiments across configurations not used for training. The repository currently has no frontend application; the structured validation API is ready for a future product UI and does not fabricate charts or empty metrics.
